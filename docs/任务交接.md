# Karuta Web 任务交接

更新时间：2026-09-10

## 当前目标

把 `HITsz-JLA/karuta-web` 部署成一个可在校园网访问的歌牌 Web 应用：

- 歌牌数据包保存在服务器本地；普通用户只读。
- 管理员使用独立的 `/admin` 页面上传数据包。
- 适配 JLA-MUCA 新版 `meta/metadata.csv` 格式。
- 正式对局歌曲最多播放 30 秒。
- 在线歌牌对战支持 1v1 房间、卡面抢牌与服务器回合音频。
- 数据包支持两种模式：
  - **完整包**：保留 full 和前 30 秒片段；对局播放片段，休息音乐播放 full。
  - **精简包**：只保留前 30 秒片段；对局和休息音乐都播放片段。

## 在线歌牌对战实现

- 当前实现分支：`feature/online-karuta-battle`，对应 GitHub Issue `#1`。
- `/online` 提供创建/加入房间、公开房间列表、双方准备、实时抢牌和结算页面；在线牌组直接使用服务器四套 MUCA 牌组的真实卡面，不以歌名替代卡面。
- `/online` 已增加闪彩风格的局部主题；开局三分钟和每回合结算后的 40 秒休息阶段，玩家只能拖动自己这一侧的牌区。3×11 是 33 个固定可放置槽位，默认隐藏未放卡槽位，拖动时显示全部槽位，并支持随机排、按名称排和固定牌位；拖动过程不广播，下一回合开始时发布最终槽位快照，对手视角按上下镜像显示，不会看到拖动过程。
- 在线牌局已按权威规则增加随机拆分、双方各选 30、30 张互换、各自 BAN 5、各自 25 张手牌；最终 50 张实牌以外抽取 20 首空牌歌曲，每首只出现一次，空牌回合点击在场卡面不判错且不移出实牌；休息歌曲从场外且不在空牌池的歌曲中抽取。
- 普通歌曲选错后由对手在 40 秒休息阶段交一张牌；正确抢到对手牌时也由获胜方在同一休息阶段交一张自己的牌给对手；未及时选择时服务端自动转牌。
- 休息阶段支持双方提前准备；双方均准备后服务端安排 5 秒倒计时，前端显示高亮倒计时并播放提示音。
- 音频播放已增加大厅手势预解锁、回合前预加载、有限重试、明确错误提示和 HTTP Range 响应；设备拦截自动播放时可点击按钮恢复。
- 在线对战已增加服务端 WebSocket Ping/Pong RTT 与抖动记录；双方样本不足或 RTT/抖动差距超阈值时禁止准备，抢牌按 `服务器收到时间 - RTT/2`（最多补偿 60ms）排序，并在首个正确操作后收集 125ms。
- Express 通过 `ws` 托管同源 `/ws`；服务端在内存维护 1v1 房间、回合、得分和一次性音频凭证。
- `/api/online/room/:code/audio/:token` 从服务器本地 ZIP 的 `seg_30` 资源读取当前歌曲，不把答案放进 `roundStart` 消息。
- 创建和加入在线房间都不要求本地导入数据包；服务端从 `metadata.csv` 生成目录，按牌组提供卡面，并按回合提供音频。
- 代码验证：`npm test`（覆盖奇数候选牌服务端弃置 1 张、20 首空牌只出现一次、错选交牌和正确收取对手牌后的反向交牌）、`npm run build`（通过）；`npm run lint` 仍有 React effect 警告，无 lint error。
- 选牌性能：在线目录由服务端提供完整牌组元数据，前端用滚动窗口化渲染完整目录，不提供“加载更多”分页，也不要求本地导入 ZIP；卡面通过服务端卡面接口按需读取。
- 浏览器 smoke：使用两个独立浏览器上下文和 60 张临时卡面，真实完成创建/加入、双方选 30、互换、BAN 5，并进入开局排牌；页面显示双方上下分置的 3×11 牌区，未放卡槽位默认隐藏，拖动我方卡面时显示全部 33 个固定槽位。

## 换设备继续的启动方式

在新设备克隆仓库后：

```powershell
npm ci
Copy-Item .env.example .env
# 编辑 .env，设置一个新的 ADMIN_PASSWORD
npm run build
```

开发测试需要开两个终端：

```powershell
# 终端 1：API 和服务器数据包服务
npm run server

# 终端 2：Vite 开发页面
npm run dev -- --host 0.0.0.0
```

浏览器访问：

- 本机：`http://127.0.0.1:5173/`
- 局域网开发页面：`http://<运行电脑的局域网 IP>:5173/`
- 局域网生产页面：`http://<运行电脑的局域网 IP>:8787/`
- 管理员：`http://<运行电脑的局域网 IP>:8787/#/admin`

生产模式可使用：

```powershell
npm run build
npm start
```

此时 Express 会在 `8787` 提供构建后的页面和 API。

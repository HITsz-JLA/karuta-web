# Karuta Web 任务交接

更新时间：2026-09-10

## 当前目标

把 `HITsz-JLA/karuta-web` 部署成一个可在校园网访问的歌牌 Web 应用：

- 歌牌数据包保存在服务器本地；普通用户只读。
- 管理员使用独立的 `/admin` 页面上传数据包。
- 适配 JLA-MUCA 新版 `meta/metadata.csv` 格式。
- 正式对局歌曲最多播放 30 秒。
- 在线歌牌对战支持 1v1 房间、卡面抢牌与服务器回合音频。
- 数据包支持两种模式：
  - **完整包**：保留 full 和前 30 秒片段；对局播放片段，休息音乐播放 full。
  - **精简包**：只保留前 30 秒片段；对局和休息音乐都播放片段。

## 在线歌牌对战实现

- 当前实现分支：`feature/online-karuta-battle`，对应 GitHub Issue `#1`。
- `/online` 提供创建/加入房间、公开房间列表、双方准备、实时抢牌和结算页面；在线牌组直接使用服务器四套 MUCA 牌组的真实卡面，不以歌名替代卡面。
- `/online` 已增加闪彩风格的局部主题；开局三分钟和每回合结算后的 40 秒休息阶段，玩家只能拖动自己这一侧的牌区。3×11 是 33 个固定可放置槽位，默认隐藏未放卡槽位，拖动时显示全部槽位，并支持随机排、按名称排和固定牌位；拖动过程不广播，进入对局及每个下一回合开始时发布最终槽位快照，对手视角按上下镜像显示，不会看到拖动过程。
- 在线牌局已按权威规则增加随机拆分、双方各选 30、30 张互换、各自 BAN 5、各自 25 张手牌；最终 50 张实牌以外抽取 20 首空牌歌曲，每首只出现一次，空牌回合没有对应场上卡面，点击任一卡面都会判错且不移出实牌；休息歌曲从场外且不在空牌池的歌曲中抽取。
- 普通歌曲选错后由对手在 40 秒休息阶段交一张牌；正确抢到对手牌时也由获胜方在同一休息阶段交一张自己的牌给对手；未及时选择时服务端自动转牌。
- 胜负判定以手牌数为准：无需换牌的收牌结算后，或完成换牌操作后某方手牌数变为 0，该方立即获胜并结束对局；服务端已覆盖这两条边界路径。
- 开局 180 秒排牌阶段与每回合 40 秒休息阶段均支持双方提前准备；右侧准备区显示双方准备状态，开局双方均准备后服务端安排 20 秒倒计时进入游戏，休息阶段双方均准备后安排 5 秒倒计时进入下一回合，前端均显示高亮倒计时并播放提示音。
- 音频播放已增加大厅手势预解锁、回合前预加载、有限重试、明确错误提示和 HTTP Range 响应；休息音乐默认使用 28% 音量，设备拦截自动播放时可点击按钮恢复。
- 选牌目录已使用窗口化渲染和更紧凑的多列卡面布局；卡面通过浏览器 Cache Storage 与服务端 immutable 缓存复用，内存对象 URL 限制为最近 96 张。
- 在线对战已增加服务端 WebSocket Ping/Pong RTT 与抖动记录；双方样本不足或 RTT/抖动差距超阈值时禁止准备，抢牌按 `服务器收到时间 - RTT/2`（最多补偿 60ms）排序，并在首个正确操作后收集 125ms。
- Express 通过 `ws` 托管同源 `/ws`；服务端在内存维护 1v1 房间、回合、得分和一次性音频凭证。
- `/api/online/room/:code/audio/:token` 从服务器本地 ZIP 的 `seg_30` 资源读取当前歌曲，不把答案放进 `roundStart` 消息。

## 2026-09-10 后续性能迭代

- `OnlineCardTile` 的远程卡面缓存改为 IntersectionObserver 懒加载，只有进入视口前 240px 才访问 Cache Storage；服务器牌组目录仍完整可滚动，不再因挂载 50 张牌而同时读取全部图片。

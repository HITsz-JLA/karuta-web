# 部署与数据包说明

## 本地目录

项目目录：

```text
E:\系统默认\桌面\karuta-web
```

服务器本地数据包目录：

```text
data-packages/
```

该目录只由 Node 服务端读取和写入。浏览器首页只能列出和下载数据包，上传入口在单独的管理员页面。

## 服务端口

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| Vite | `0.0.0.0:5173` | 开发页面；`/api` 代理到 8787 |
| Express | `0.0.0.0:8787` | 登录、上传、数据包列表、生产页面 |

校园网设备访问时，使用运行服务电脑的局域网 IPv4 地址，不要使用 `127.0.0.1`。当前测试过的访问形式是：

```text
http://<局域网 IPv4>:5173/
http://<局域网 IPv4>:5173/#/admin
http://<局域网 IPv4>:8787/
http://<局域网 IPv4>:8787/#/admin
```

浏览器从服务器读取 ZIP 时，首页会对 `/api/packages/<包名>/download` 使用 8 MB 的 HTTP Range 分块请求，逐块校验后再交给 ZIP 导入器；页面会显示当前下载进度。服务器端需要保留 `Accept-Ranges: bytes` 和正确的 `Content-Range` 响应。

如果导入时出现 IndexedDB connection closing，应用会自动重新打开数据库并重试一次；仍失败时请关闭同一站点的其他标签页，执行 `Ctrl+F5`，必要时仅清理该站点的 IndexedDB 后重新导入，不要清理整个浏览器配置。

## 管理员配置

推荐在项目根目录创建未提交的 `.env`：

```dotenv
ADMIN_PASSWORD=请替换为强密码
PORT=8787
HOST=0.0.0.0
MAX_UPLOAD_MB=2048
```

如果没有配置 `ADMIN_PASSWORD`，服务端会随机生成密码并保存到：

```text
data-packages/.admin-password
```

这个文件已加入 `.gitignore`，不能依赖 Git 在设备之间同步。

## JLA-MUCA 新版包结构

远程服务器当前数据包位于：

```text
/root/HITSZ-JLA/JLA-MUCA/
```

新版 ZIP 适配时应保留以下逻辑：

```text
meta/metadata.csv                 # 歌曲、作品、牌号映射
mp3_files/full/<category>/       # 完整音频
mp3_files/seg_30/<category>/     # 前 30 秒片段
music_cover/<category>/          # 封面
```

`metadata.csv` 的关键字段：

```text
category, work_number, work_name, song_slot, song_title,
audio_file, audio_path, cover_files, cover_paths
```

导入规则：同一个 `category + work_number` 是一张牌；多个 `song_slot` 合并到该牌。`cover_paths` 和 `audio_path` 是 ZIP 内相对路径，ZIP 外层目录名不应影响匹配。

## 两种数据包模式

| 模式 | 包内音频 | 正式对局 | 休息音乐 |
| --- | --- | --- | --- |
| 完整包 | full + seg_30 | seg_30，最多 30 秒 | full，播放完整歌曲 |
| 精简包 | 仅 seg_30 | seg_30，最多 30 秒 | seg_30，最多 30 秒 |

建议在 ZIP 中放置一个 manifest 记录模式，同时服务器上传记录也保存模式；这样即使包内目录同时存在 full 和 seg_30，导入器仍能按管理员的选择工作。

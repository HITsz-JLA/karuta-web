# Karuta Web 任务交接

更新时间：2026-09-08

## 当前目标

把 `HITsz-JLA/karuta-web` 部署成一个可在校园网访问的歌牌 Web 应用：

- 歌牌数据包保存在服务器本地；普通用户只读。
- 管理员使用独立的 `/admin` 页面上传数据包。
- 适配 JLA-MUCA 新版 `meta/metadata.csv` 格式。
- 正式对局歌曲最多播放 30 秒。
- 数据包支持两种模式：
  - **完整包**：保留 full 和前 30 秒片段；对局播放片段，休息音乐播放 full。
  - **精简包**：只保留前 30 秒片段；对局和休息音乐都播放片段。

## 换设备继续的启动方式

在新设备克隆仓库后：

```powershell
npm ci
Copy-Item .env.example .env
# 编辑 .env，设置一个新的 ADMIN_PASSWORD
npm run build
```

开发测试需要开两个终端：

```powershell
# 终端 1：API 和服务器数据包服务
npm run server

# 终端 2：Vite 开发页面
npm run dev -- --host 0.0.0.0
```

浏览器访问：

- 本机：`http://127.0.0.1:5173/`
- 局域网开发页面：`http://<运行电脑的局域网 IP>:5173/`
- 局域网生产页面：`http://<运行电脑的局域网 IP>:8787/`
- 管理员：`http://<运行电脑的局域网 IP>:8787/#/admin`

生产模式可使用：

```powershell
npm run build
npm start
```

此时 Express 会在 `8787` 提供构建后的页面和 API。

## 注意事项

- 不要提交 `keygura.pem`、`.env`、`data-packages/.admin-password` 或任何 ZIP 数据包。
- 当前电脑的管理员自动生成密码保存在被忽略的 `data-packages/.admin-password`；换设备后应在新设备重新设置 `ADMIN_PASSWORD`。
- 若要在远程服务器部署，需要另外配置 Node.js、项目目录、systemd/进程守护和远程防火墙；当前改动尚未推送到远程服务器运行环境。
